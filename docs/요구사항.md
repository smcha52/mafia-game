## 2. 직업별 능력

### 2.1 시민 (Citizen)

- 특별한 능력이 없다.
- 낮 토론과 투표를 통해 마피아 진영을 찾아야 한다.

### 2.2 마피아 (Mafia)

- 밤마다 제거할 대상을 선택한다.
- 살아 있는 마피아들이 투표한 대상을 공격한다.
- 가장 많은 표를 받은 사람이 공격 대상이 된다.
- **동점이면 아무도 공격하지 않는다.**
- 마피아끼리는 서로의 닉네임을 볼 수 있다.
- 스파이가 누구인지도 알 수 있다.

### 2.3 경찰 (Police)

- 밤마다 살아 있는 사람 한 명을 조사한다.
- 조사 결과는 `시민 진영` / `마피아 진영` / `중립 진영` 중 하나로 표시한다.
- **스파이를 조사하면 `마피아 진영`으로 표시한다.**
- **광대를 조사하면 `중립 진영`으로 표시한다.**
- 조사 결과는 경찰 본인에게만 보인다.

### 2.4 의사 (Doctor)

- 밤마다 살아 있는 사람 한 명을 치료한다.
- 마피아의 공격 대상과 치료 대상이 같으면 공격 대상은 살아남는다.
- **자기 자신도 치료할 수 있다.**
- **같은 사람을 연속된 밤에 치료할 수 없다.**

### 2.5 경호원 (Bodyguard)

- 밤마다 **자신을 제외한** 살아 있는 사람 한 명을 보호한다.
- 보호 대상이 마피아에게 공격받으면 보호 대상은 살아남고 **경호원이 대신 사망**한다.
- **같은 사람을 연속된 밤에 보호할 수 없다.**
- 이미 죽은 사람은 보호할 수 없다.

### 2.6 탐정 (Detective)

- 밤마다 **서로 다른** 생존자 두 명을 선택한다.
- 두 사람이 같은 진영인지 다른 진영인지만 확인한다.
- **정확한 직업은 보여주지 않는다.**

결과 예시:

```text
두 사람은 같은 진영입니다.
```

```text
두 사람은 서로 다른 진영입니다.
```

> 진영 비교 시 중립(광대)은 시민·마피아 어느 쪽과도 "다른 진영"으로 판정한다. (§2.10 참조)

### 2.7 기자 (Reporter)

- **게임 중 단 한 번만** 능력을 사용할 수 있다.
- 밤에 살아 있는 사람 한 명을 취재 대상으로 선택한다.
- 다음 날 아침 해당 플레이어의 **정확한 직업을 모든 생존자에게 공개**한다.
- **기자가 능력을 사용한 밤에 사망해도 취재 결과는 공개한다.**
- 능력을 사용한 뒤에는 일반 시민처럼 참여한다.

### 2.8 영매 (Medium)

- 밤마다 **사망자** 한 명을 선택한다.
- 선택한 사망자의 **정확한 직업**을 확인한다.
- 확인 결과는 영매 본인에게만 보인다.
- **아직 사망자가 없으면 능력을 사용할 수 없다.**

### 2.9 스파이 (Spy)

- 스파이는 **마피아 진영**이다.
- 마피아와 스파이는 서로의 정체를 알고 있다.
- **밤에 마피아의 공격 투표에 참여하지 않는다.**
- 낮의 처형 투표에서 생존자 한 명을 선택한다.
- **투표를 확정하는 순간**, 자신이 투표한 사람의 정확한 직업을 즉시 확인한다.
- 확인 결과는 스파이 본인에게만 보인다.
- **투표를 제출한 뒤에는 대상을 변경할 수 없다.**
- **하루에 한 번만** 직업을 확인할 수 있다.
- 마피아 진영의 승리 조건을 함께 적용받는다.
- 경찰이 스파이를 조사하면 `마피아 진영`으로 표시한다.

스파이 화면 예시:

```text
투표가 완료되었습니다.

당신이 투표한 '리안'님의 직업은
경찰입니다.

이 정보는 스파이에게만 보입니다.
```

### 2.10 광대 (Jester)

- 시민과 마피아 어느 쪽에도 속하지 않는 **중립 진영**이다.
- **낮의 처형 투표로 처형되면 광대가 즉시 단독 승리**한다.
- **밤에 마피아에게 살해되면 승리하지 못한다.**
- 광대가 처형되면 일반 승리 조건 확인보다 **먼저** 광대 승리를 처리하고 게임을 종료한다.
- 경찰 조사 결과는 `중립 진영`으로 표시한다.
- 탐정의 진영 비교에서도 별도의 중립 진영으로 취급한다.

## 3. 능력 처리 순서

밤 결과는 반드시 다음 순서로 처리한다.

| 순서 | 처리 내용 |
|---|---|
| 1 | 마피아 공격 대상 확정 |
| 2 | 의사 치료 대상 확인 |
| 3 | 경호원 보호 대상 확인 |
| 4 | 공격 대상 생존 또는 사망 계산 |
| 5 | 경호원의 대신 사망 처리 |
| 6 | 경찰 조사 결과 전달 |
| 7 | 탐정 조사 결과 전달 |
| 8 | 영매 조사 결과 전달 |
| 9 | 기자 취재 결과를 다음 날 공개 목록에 저장 |
| 10 | 승리 조건 확인 |
| 11 | 낮 결과 화면으로 이동 |

### 3.1 의사·경호원 중복 적용 규칙

의사의 치료와 경호원의 보호가 **같은 공격 대상에게 동시에 적용되면**:

1. **의사의 치료를 먼저 적용**한다 → 공격 대상 생존
2. **경호원은 사망하지 않는다**

### 3.2 처리 결과 조합표

| 공격 대상 | 의사 치료 | 경호원 보호 | 결과 |
|---|---|---|---|
| A | — | — | A 사망 |
| A | A | — | A 생존, 사망자 없음 |
| A | — | A | A 생존, **경호원 사망** |
| A | A | A | A 생존, **경호원 생존**, 사망자 없음 |
| 없음(동점) | 무관 | 무관 | 사망자 없음 |

## 4. 승리 조건

**검사 순서: 광대 → 시민 → 마피아**

### 4.1 광대 승리 (최우선 검사)

```text
광대가 낮 처형 투표로 처형됨
```

- 즉시 광대 단독 승리, 게임 종료.
- 밤에 마피아에게 살해된 경우는 승리하지 않는다.

### 4.2 시민 진영 승리

```text
살아 있는 마피아 진영 인원이 0명
```

- 마피아와 스파이가 **모두** 사망해야 한다.

### 4.3 마피아 진영 승리

```text
살아 있는 마피아 진영 인원 수 >= 살아 있는 시민 진영 인원 수
```

- **광대는 시민 진영과 마피아 진영의 생존 인원 계산에서 제외한다.**

> **D-2 (미정의)**: 낮 처형 투표가 동점일 때의 처리 규칙이 정해지지 않았다.
> 후보 — (a) 아무도 처형하지 않음, (b) 재투표 1회 후 동점이면 처형 없음, (c) 무작위 선택.
> 이 규칙은 광대의 승률에 직접 영향을 주므로 구현 전 확정 필요.

## 6. 비밀정보 보안

### 6.1 열람 권한 매트릭스

| 정보 | 열람 가능 대상 |
|---|---|
| 자신의 정확한 직업 | 본인만 |
| 마피아 진영 구성원 목록 | 마피아, 스파이만 |
| 경찰 조사 결과 | 해당 경찰만 |
| 탐정 조사 결과 | 해당 탐정만 |
| 영매 조사 결과 | 해당 영매만 |
| 스파이 직업 확인 결과 | 해당 스파이만 |
| 밤 행동 대상 | 제출 본인 + 결과 처리 권한 |
| 기자 공개 결과 | **모든 참가자** |
| 밤 사망자 목록 | **모든 참가자** |

### 6.2 필수 보안 원칙

- 일반 참가자가 **브라우저 개발자 도구로 다른 사람의 직업이나 행동 결과를 읽을 수 없어야** 한다.
- **클라이언트 화면에서 숨기기만 하는 방식은 보안으로 인정하지 않는다.**
- 죽은 플레이어는 능력과 투표를 사용할 수 없다. (서버에서 차단)
- 능력 사용 횟수(`abilityUsed`)와 연속 대상 제한(`lastTargetId`)을 **서버 데이터로 검증**한다.
- 공개 정보와 비밀정보가 같은 경로에 섞이지 않도록 분리한다.

### 6.3 서버 검증이 필요한 규칙

| 규칙 | 검증 대상 |
|---|---|
| 기자 1회 제한 | `abilityUsed` |
| 의사 연속 치료 금지 | `lastTargetId` |
| 경호원 연속 보호 금지 | `lastTargetId` |
| 경호원 자기 보호 금지 | 대상 uid ≠ 본인 uid |
| 탐정 두 대상 상이 | `detectiveTargets[0] ≠ [1]` |
| 영매 대상은 사망자만 | 대상의 `alive == false` |
| 사망자 행동 차단 | 본인의 `alive == true` |
| 스파이 투표 변경 금지 | 제출 후 write 거부 |
| 스파이 1일 1회 확인 | 일자별 제출 기록 |

### 6.4 구현 방식 — Supabase (확정)

| 논리 요구사항 | 구현 수단 |
|---|---|
| 본인만 읽기 | RLS `USING (auth.uid() = uid)` |
| 진영 기반 읽기 (마피아 명단) | RLS 정책 내 `EXISTS` 서브쿼리 |
| 밤 11단계 결과 처리 | `SECURITY DEFINER` Postgres 함수 (트랜잭션 1회) |
| 능력 제약 검증 (§6.3) | 동일 함수 내 검증 + CHECK 제약 |
| 실시간 동기화 | Realtime `postgres_changes` 구독 |
| 대기실 접속자 표시 | Realtime **Presence** |
| 참가자 인증 | 익명 로그인 (`signInAnonymously`) |

핵심 원칙:

- 모든 테이블은 **RLS를 활성화**하고, 기본은 전면 거부 후 필요한 정책만 추가한다.
- 클라이언트는 밤 행동을 **직접 INSERT 하지 않고** RPC 함수를 호출한다. 제약 검증을 클라이언트가 우회할 수 없게 한다.
- 밤 결과 처리 함수는 `SECURITY DEFINER`로 두어, 호출자 권한으로는 읽을 수 없는 비밀 데이터를 함수 내부에서만 다룬다.
- 프로젝트 URL과 `anon` 키는 환경변수(`.env`)로 관리하고 저장소에 커밋하지 않는다. `service_role` 키는 클라이언트에 **절대 포함하지 않는다**.

> 요구사항 원문에 있던 Firebase Security Rules 표기는 위 Supabase 방식으로 대체한다.
> §6.1~§6.3의 요구사항 자체는 변경 없이 그대로 적용된다.

## 7. 데이터 항목

### 7.1 공개 영역

```text
players/{uid}/team           # CITIZEN | MAFIA | NEUTRAL
players/{uid}/alive          # boolean
players/{uid}/abilityUsed    # boolean (기자 등 1회성 능력)
players/{uid}/lastTargetId   # 직전 밤 대상 (의사/경호원 연속 제한)

publicResults/reporterReveal # 기자 취재 공개 결과
publicResults/nightDeaths    # 밤 사망자 목록
```

> `players/{uid}/team`은 공개 영역이지만, 이 값이 노출되면 진영이 그대로 드러난다.
> **게임 종료 시점에만 공개**하고, 진행 중에는 비밀 영역에서 관리할 것을 권장한다. (구현 시 재검토 항목)

### 7.2 비밀 영역 — 본인만 읽기

```text
privateRoles/{uid}/role               # 정확한 직업
```

## 8. 구현 순서

### 8.1 1단계 — 기반 (직업보다 먼저 완성) ✅ 구현 완료

| # | 항목 | 구현 위치 |
|---|---|---|
| 1 | 온라인 방 생성/입장 | `create_room` / `join_room` RPC, `HomePage.jsx` |
| 2 | 대기실 및 참가자 동기화 | Realtime 구독, `useRoom.js` |
| 3 | 준비 상태 표시 | `set_ready` RPC, `PlayerList.jsx` |
| 4 | 게임 시작 | `start_game` RPC (방장·인원·준비 검증) |
| 5 | 재접속 복원 | `my_active_room` RPC + 세션 유지 |

> **1단계가 정상 작동하기 전에는 직업 기능을 구현하지 않는다.**

### 8.2 2단계 — 직업 (하나씩 완성 후 다음으로)

| 순서 | 직업 |
|---:|---|
| 1 | 마피아와 시민 |
| 2 | 경찰 |
| 3 | 의사 |
| 4 | 경호원 |
| 5 | 탐정 |
| 6 | 기자 |
| 7 | 영매 |
| 8 | 스파이 |
| 9 | 광대 |
| 10 | 전체 직업 조합과 승리 조건 테스트 |

**직업 기능을 한꺼번에 구현하지 않는다. 하나를 완성하고 테스트한 뒤 다음 직업으로 넘어간다.**

### 8.3 직업별 테스트 체크리스트

각 직업을 추가할 때마다 아래를 모두 테스트한다.

- [ ] 동시 제출
- [ ] 새로고침 후 결과 복원
- [ ] 승리 조건과의 충돌
- [ ] 모바일 화면 표시
- [ ] RLS 정책

## 9. 미해결 엣지 케이스

구현 전 확정이 필요한 항목.

### 9.1 처형 투표 동점 (D-2)

§4.3 참조. 광대 승률에 직접 영향.

### 9.2 기자가 광대를 취재한 경우 (D-3)

기자가 광대의 직업을 전체 공개하면, 이후 아무도 광대에게 투표하지 않아 **광대의 승리 경로가 사실상 차단**된다.
후보 — (a) 그대로 공개(광대 패널티로 수용), (b) 광대는 시민으로 위장 공개, (c) 취재 대상에서 제외.

### 9.3 경호원이 공격 대상인 경우

경호원은 자기 자신을 보호할 수 없으므로, 경호원 본인이 공격당하면 의사 치료가 없는 한 사망한다. — **명세대로 처리, 예외 없음.**

### 9.4 마피아 전원 사망 후 스파이만 생존

스파이는 밤 공격에 참여하지 않으므로 공격이 발생하지 않는다.
마피아 진영 생존 1명이 되며, 시민 진영 생존이 1명 이하로 줄면 §4.3에 의해 마피아 진영 승리. — **명세대로 처리.**

### 9.5 영매가 확인할 사망자가 없는 밤

능력 사용 불가. 제출 없이 밤을 넘긴다. — **명세대로 처리.**
